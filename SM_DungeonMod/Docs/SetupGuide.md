# SM_DungeonMod — установка на сервер

Гайд для владельца сервера: сборка PBO, установка, первый запуск, привязка
готовых локаций.

## Что это

Система регистрации и группового прохождения подземелий на уже
подготовленных локациях: соло / группа по приглашениям / поиск спутников,
бронирование слотов на неделю, телепорт и обратный отсчёт, защита зоны от
посторонних, доп. наполнение (объекты/заражённые/животные) из экспорта
COT/VPP, командная эвакуация, распределение добычи как в WoW и наградные
билеты, штрафы за неявку/выход, админ-вкладка в самом меню.

## Важно: этот репозиторий содержит ИСХОДНИКИ, не готовый PBO

В отличие от некоторых других модов этой команды, `config.cpp` здесь лежит
как читаемый исходник (а не бинарный `config.bin`). Это осознанный выбор:
исходник проще поддерживать и просматривать в git. Перед установкой на
сервер его нужно один раз собрать в PBO любым из привычных способов:

- **DayZ Tools** (Steam, бесплатно) → `Addon Builder`: указываете папку
  `SM_DungeonMod`, на выходе получаете `SM_DungeonMod.pbo`.
- Или **Mikero's DePbo Tools** (`makepbo`), если уже используете их для
  других модов.
- На большинстве серверных движков PBO с "сырым" (небинаризованным)
  `config.cpp` тоже загружается и работает — это чуть медленнее по
  времени старта, но для тестирования подходит. Для продакшена
  рекомендуется полноценная сборка через Addon Builder.

Иконки в `GUI/icons/*.paa` — не включены (создать `.paa`-текстуру можно
только специализированными инструментами вроде `TexView2`/`ImageToPAA` из
DayZ Tools, они не текстовые файлы и не могут быть сгенерированы как код).
Мод полностью работает и без них — там, где иконки не заданы, просто не
будет картинки на кнопке.

## Быстрая установка

1. Соберите `SM_DungeonMod.pbo` (см. выше) и положите в:

   ```text
   @SM_DungeonMod\addons\SM_DungeonMod.pbo
   ```

2. Остановите сервер.
3. Загрузите папку `@SM_DungeonMod` в корень сервера (и игрокам, раз мод
   меняет клиентский интерфейс).
4. Добавьте мод в параметры запуска сервера и клиента:

   ```text
   -mod=@SM_DungeonMod
   ```

   Если уже есть другие моды:

   ```text
   -mod=@CF;@SM_PartyMod;@SM_DungeonMod
   ```

5. Запустите сервер один раз — создастся конфиг:

   ```text
   $profile\SM_DungeonMod\Settings.json
   ```

6. Остановите сервер, настройте `Settings.json` (см. `Docs/ConfigGuide.md`) —
   как минимум замените `REPLACE_WITH_STEAMID64` в `General.AdminUids` на
   реальный SteamID64 админа, и настройте хотя бы один данж (или включите
   встроенный `example_camp`, заполнив координаты своей локации).
7. Запустите сервер снова.

## Где лежат файлы мода на сервере

```text
$profile\SM_DungeonMod\Settings.json   - вся конфигурация (данжи, сложности, штрафы, расписание)
$profile\SM_DungeonMod\Bookings.json   - активные и недавние брони
$profile\SM_DungeonMod\Invites.json    - висящие приглашения
$profile\SM_DungeonMod\Players.json    - разблокировки, штрафы, КД игроков
```

Все три `.json`-файла базы (Bookings/Invites/Players) можно спокойно
удалить при остановленном сервере, если нужно сбросить прогресс — они
пересоздаются пустыми при следующем старте.

## Подготовка локации (COT / VPP)

Мод не создаёт геометрию подземелья сам — он рассчитан на **уже
готовую, отдельно построенную вами локацию** на карте (база, бункер,
завод и т.п.), собранную через COT (Community Online Tools) или
VPP Admin Tools.

1. Постройте локацию любым удобным способом (эти инструменты — не часть
   этого мода, ставятся отдельно).
2. Определите координаты:
   - точку(и) телепортации на вход (по одной на каждого потенциального
     участника группы);
   - точку и радиус эвакуации (место сбора выживших);
   - центр и радиус/высоту зоны, которую нужно защищать от посторонних.
3. Если хотите доп. наполнение (объекты/заражённые/животные) — экспортируйте
   расставленные объекты из вашего инструмента в JSON.
4. Если формат экспорта не совпадает "из коробки" с ожидаемым (см.
   `Docs/ConfigGuide.md`, раздел "Доп. наполнение"), прогоните файл через:

   ```bash
   python TOOLS/convert_location.py cot_export.json SM_DungeonMod/Locations/my_dungeon.json
   ```

5. Пропишите все координаты и путь к JSON в `Settings.json` (см. пример
   `example_camp` — он уже полностью заполнен как шаблон, скопируйте его
   структуру для своего данжа).

## Обновление конфига без рестарта

Админ (uid из `General.AdminUids`) может:

- написать в обычный игровой чат `!dungeonreload` (или `!smdreload`);
- либо нажать "Перезагрузить конфиг" во вкладке "Админ" открытого меню
  мода (по умолчанию клавиша `J`, настраивается в контролах DayZ).

Оба способа перечитывают `Settings.json` "на лету", без рестарта сервера.
