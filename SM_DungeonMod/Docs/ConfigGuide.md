# SM_DungeonMod — справочник по Settings.json

Файл: `$profile\SM_DungeonMod\Settings.json`. Пересоздаётся с полями по
умолчанию при первом старте и при каждом `!dungeonreload`, если каких-то
полей не хватает — так что можно смело удалять целые секции и запускать
`!dungeonreload`, чтобы получить дефолты обратно.

## General

| Поле | Что делает |
|---|---|
| `Enabled` | Общий выключатель мода (пока не используется как жёсткий гейт везде — оставлен на будущее/для внешних проверок). |
| `AdminUids` | Список SteamID64, которым доступна вкладка "Админ" (перезагрузка конфига, вкл/выкл данжа, форс-отмена/эвакуация, помилование). |
| `MaxActiveBookingsPerPlayer` | Сколько активных (не завершённых) броней может держать один игрок одновременно — как лидер или как участник. |
| `InviteTimeoutSeconds` | Через сколько секунд приглашение в группу протухает само. |
| `GroupFinderListingTimeoutSeconds` | Зарезервировано под будущую авточистку старых объявлений поиска спутников. |
| `ConfigReloadCooldownSeconds` | Зарезервировано (сейчас `!dungeonreload` не ограничен по частоте отдельно от общей нагрузки). |

## Notifications

| Поле | Что делает |
|---|---|
| `WarnBeforeStartSeconds` | За сколько секунд до времени брони всем участникам приходит уведомление "Забег начнётся скоро". |
| `CountdownSeconds` | Длительность финального отсчёта прямо перед телепортацией в данж. |
| `NoShowGraceMinutes` | После времени старта брони мод ждёт ещё это время, пока не соберутся все записавшиеся — но если все уже онлайн, ждать не нужно, забег стартует сразу. По истечении срока забег стартует с теми, кто есть, а отсутствующие получают штраф за неявку. |

## Booking (еженедельный календарь)

| Поле | Что делает |
|---|---|
| `BookingWindowDays` | На сколько дней вперёд можно бронировать слоты. |
| `DayStartHour` / `DayEndHour` | В какие часы суток (0-24) вообще существуют слоты. |
| `SlotDurationMinutes` | Длительность одного слота/брони — используется и для проверки пересечений. |
| `SlotIntervalMinutes` | Шаг между началами слотов (может быть меньше `SlotDurationMinutes`, если хотите более гибкое расписание). |
| `RestartBufferMinutes` | Слоты, попадающие в этот буфер вокруг времени рестарта, не предлагаются игрокам. |
| `RestartTimesUTC` | Список времён рестартов сервера в UTC, формат `"HH:MM"`. |

Подземелье — это одна физическая локация, поэтому пересечения считаются
**по каждому данжу отдельно**: два разных данжа могут иметь параллельные
брони на одно и то же время, а один и тот же данж — нет.

## Penalties

| Поле | Что делает |
|---|---|
| `Enabled` | Общий выключатель штрафов. |
| `NoShowLockMinutes` | Временная блокировка очереди за неявку на свою бронь. |
| `EarlyLeaveLockMinutes` | Временная блокировка за выход из данжа во время активного забега (или дисконнект во время него). |
| `OffensesBeforePermaBan` | Сколько "непросроченных" нарушений подряд ведут к постоянному бану очереди. |
| `OffenseDecayDays` | Через сколько дней старое нарушение перестаёт учитываться в счётчике перманентного бана. |

Постоянный бан и временные блокировки снимаются только вручную —
вкладка "Админ" → "Штрафы" → "Снять штраф".

## Ticket

| Поле | Что делает |
|---|---|
| `ItemClassName` | Класс предмета-билета, который выдаётся победителю ролла (по умолчанию `SM_DungeonRewardTicket`, определён в этом же моде). |

## Dungeons[] — один элемент на подземелье

| Поле | Что делает |
|---|---|
| `Id` | Уникальный текстовый идентификатор — используется в разблокировках и КД, не меняйте после того, как игроки начали проходить данж. |
| `Name`, `Description` | Отображаемое название и описание (можно ключ `#STR_...` или обычный текст). |
| `Enabled` | Показывается ли данж обычным игрокам (админы видят выключенные тоже, чтобы включить обратно). |
| `MinPlayers` / `MaxPlayers` | Минимум игроков для старта забега / максимальный размер группы. |
| `AllowSolo` / `AllowInviteGroup` / `AllowGroupFinder` | Какие из трёх режимов записи доступны для этого данжа. |
| `RequiresUnlock` | Если `true`, данж недоступен, пока не окажется в списке разблокированных у игрока (см. `Difficulties[].UnlocksDungeonIds`). |
| `RunTimeLimitMinutes` | Жёсткий лимит на весь забег — по истечении забег проваливается и всех телепортирует обратно. |
| `CooldownMinutesPerPlayer` | После успешного прохождения игрок не может снова забронировать этот же данж это время. |
| `Zone` | `Center` (вектор), `RadiusMeters`, `HeightMeters` — цилиндр защиты от посторонних (активен только пока идёт активный забег). |
| `Entry.TeleportPositions[]` | Точки телепортации на вход, по одной на слот группы (если участников больше точек — используются по кругу). |
| `Entry.OrientationYaw` | Направление взгляда при телепортации. |
| `Evacuation.ExitPosition` / `RadiusMeters` / `HoldSeconds` | Точка сбора для командной эвакуации, радиус "все должны быть внутри" и сколько секунд удерживать. |
| `ExtraContent.Enabled` | Спавнить ли доп. наполнение вообще. |
| `ExtraContent.ImportFile` | Путь к JSON-экспорту из COT/VPP (см. ниже). |
| `ExtraContent.ManualPoints[]` | Точки, прописанные вручную прямо в конфиге (в дополнение к импорту). |
| `Difficulties[]` | См. ниже. |

## Difficulties[] — сложности внутри одного данжа

| Поле | Что делает |
|---|---|
| `Name` | Отображаемое имя сложности. |
| `OutgoingDamageMultiplier` | Множитель урона, который **наносит игрок** внутри этого данжа на этой сложности (1.0 = без изменений, 0.5 = вдвое слабее). Ниже — как это на самом деле реализовано и какие есть ограничения. |
| `DropChanceMultiplier` | Множитель к `DropChance` каждого предмета в `Loot[]` на этой сложности. |
| `UnlocksDungeonIds[]` | Список Id других данжей, которые открываются успешным прохождением на этой сложности. |
| `Loot[]` | Таблица наград: `ClassName`, `MinQuantity`/`MaxQuantity`, `DropChance` (0..1), `NeedGreedRoll` (true = разыгрывается между выжившими Нужно/Не откажусь/Откажусь, false = сразу случайному выжившему без ролла). |

## Доп. наполнение: формат `ExtraContent.ImportFile`

Официально поддерживается один канонический JSON:

```json
{ "Objects": [
    { "ClassName": "Wooden_Crate", "Position": [7500.1, 12.4, 8300.5], "Orientation": [0, 90, 0] }
]}
```

COT и VPP Admin Tools — сторонние моды с собственным (и иногда меняющимся)
форматом экспорта. Загрузчик мода дополнительно понимает несколько частых
альтернативных ключей (`Name`/`Type` вместо `ClassName`, `Pos`/`Ori` вместо
`Position`/`Orientation`, обёртки `{"Data":[...]}`/`{"Items":[...]}`), но
если ваш конкретный экспорт всё равно не подхватывается — один раз
прогоните его через `TOOLS/convert_location.py` (см. `SetupGuide.md`),
он сам определяет наиболее вероятные поля или принимает их явно флагами.

Один и тот же вызов спавна используется для статических объектов,
заражённых и животных — тип точки в самом экспорте не важен, важен
только `ClassName` (например `ZmbM_SoldierNormal` для зомби или `Cow_ETON`
для животного — заражённые/животные будут вести себя как обычные ИИ
DayZ после спавна).

## Известные ограничения (что стоит проверить на своей версии сервера)

Мод написан и вычитан вручную, без доступа к DayZ Tools/компилятору в
этой среде — большая часть кода использует API, уже подтверждённо
рабочие в этом же репозитории (JsonFileLoader, ScriptRPC, CreateObjectEx,
TextListboxWidget и т.д.). Но два места стоит явно протестировать перед
продакшеном:

1. **`OutgoingDamageMultiplier`** (`Scripts/4_World/SM_DungeonCreatureHooks.c`).
   Реализовано через компенсацию урона ПОСЛЕ его применения движком
   (`GetHealth`/`AddHealth` до и после `super.EEHitBy`), а не через прямую
   правку `TotalDamageResult` до применения — так надёжнее относительно
   разных версий движка. Следствие: одиночный удар, который убил бы цель
   при множителе 1.0, всё равно убьёт её и при множителе 0.5 (компенсация
   не "воскрешает"). На практике множитель ощутимо влияет на серии из
   нескольких попаданий (типичный бой с зомби/животным), но не
   гарантированно предотвращает добивание уже почти мёртвой цели одним
   ударом.
2. **Экшен открытия билета** (`ActionOpenDungeonTicket`, наследуется от
   `ActionInteractBase`, по образцу уже существующего в репозитории
   `ActionSetClanBase`). Условия/цель настроены как "действие на сам
   предмет, без внешней цели" (`CCTNone`) — стоит один раз проверить в
   игре, что "Открыть билет" действительно появляется в контекстном меню
   предмета в инвентаре.

Обе точки изолированы и не влияют на остальную логику мода (бронирование,
приглашения, поиск спутников, эвакуацию, штрафы) — если что-то из этого
не заработает "из коробки" на вашей версии игры, это не потребует
переделывать что-либо ещё.

3. **Родительский класс билета** (`config.cpp`, `SM_DungeonRewardTicket: Slip`).
   `Slip` выбран как лёгкий "бумажный" ванильный класс, но если у вашей
   версии игры класс с таким именем не существует, Addon Builder сразу
   покажет ошибку "ancestor class not found" ещё на этапе сборки PBO (то
   есть до попадания на живой сервер). Правится за 30 секунд — замените
   `Slip` на любой другой существующий простой предмет (например `Rag`
   или `Battery9V`) в строке `class SM_DungeonRewardTicket: Slip`.

## GUI-иконки

`GUI/icons/` в этом моде **пуст** — `.paa` это бинарный формат текстур
DayZ, который нельзя сгенерировать как текст/код. Кнопки меню работают и
без иконок (просто без картинки). Если нужны иконки, экспортируйте PNG в
`.paa` через `TexView2` (входит в DayZ Tools) и подключите пути в
`GUI/layouts/*.layout`.
