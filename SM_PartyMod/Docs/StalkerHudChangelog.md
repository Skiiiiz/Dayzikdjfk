# Сталкерский (PDA) рескин интерфейса SM_PartyMod

## Версия 2 — палитра из дизайн-канваса (медь/янтарь, без зелёного)

Первая версия рескина (см. историю коммитов) использовала фосфорно-зелёный
акцент. По итогам ревью дизайн-макета (Artifact "SM_PartyMod PDA Redesign")
акцент полностью заменён: **зелёного больше нигде нет** — ни в акцентах, ни
в базовых тонах панелей/рамок/текста. Палитра пересобрана заново из чистых
исходников PBO (не поверх версии 1), чтобы не накапливать артефакты двойной
трансформации:

| Роль | Значение |
|---|---|
| Основной акцент (медь) | `#b87333` |
| Вторичный акцент (янтарь, предупреждения) | `#e8b545` |
| Опасность (не трогали) | исходные красные тона мода |
| Тёмный фон панелей | тёплый уголь `#161310` / `#1c1814` |
| Рамки | тёплый тёмно-коричневый `#3a3128` |
| Текст (основной/вторичный/третичный) | тёплый бежевый `#ece4d8` / `#b3a692` / `#8a7d6a` |

Значения подобраны так, чтобы совпадать с токенами из опубликованного
дизайн-макета, а не заново «на глаз».

## Метод

Цвета переносятся детерминированным алгоритмом по группам исходного дизайна
(`TOOLS/stalker_theme.py`, не входит в PBO), применённым к нетронутым
исходникам PBO:

- нейтральные тёмные фоны (сине-серая гамма) → тёплый уголь/тёмно-коричневый;
- почти белый текст → тёплый бежевый;
- насыщенный оранжевый акцент (исходный бренд-цвет мода) → медь;
- мятно-бирюзовый и одиночные синие/зелёные акценты → янтарь (единая вторая
  краска, третьего оттенка сознательно нет);
- чистый красный (unconscious/sold out/ошибки) — **не тронут**, остаётся
  индикатором опасности.

## Ручные исключения (важно!)

Автоматический алгоритм классифицирует цвет только по HSV-паттерну, поэтому
несколько мест **осознанно** поправлены вручную после прогона скрипта, чтобы
не потерять смысловую разницу состояний:

- статус «Кровотечение» на HUD участника (`SM_ClanHud.c`) — янтарный, не
  медный, чтобы отличаться от «здоров»;
- 1-е место в топах и метка «Лидер клана» (`SM_ClanMenu.c`) — янтарные
  (золото), 3-е место оставлено на автоматической тёмной меди (естественно
  читается как «бронза»), 2-е — нейтральный светлый (серебро);
- серверный магазин: строка «лимит покупки достигнут» — янтарная
  (предупреждение), а не медная (обычно означает «доступно»);
- дефолтный цвет чужих ников в глобальном чате (`ChatColorGlobalPlayer`,
  ранее ярко-зелёный `100,255,100` в трёх местах `SM_PartyConfig.c` и
  `SM_ClanClientData.c`) — заменён на янтарь.

`SM_ClanColors` (выбираемые цвета клана, 7 разных оттенков) и
`GetDefaultPlayerTitleColor` (палитра рангов игрока) **не тронуты** —
это функциональные данные для визуального различения кланов/рангов, а не
элемент оформления; их насильное сведение к меди/янтарю сломало бы саму
задачу этих палитр (дать каждому клану/рангу свой узнаваемый цвет).

## Структура меню — уже была близка к макету

При переносе выяснилось, что вкладки `SM_ClanMenu` **уже устроены как левая
вертикальная панель навигации** (`TabMyClanBtn`, `TabMarketBtn`,
`TabAuctionBtn` и т.д., все на `x=22`, друг под другом) с иконками из
`GUI/icons/nav_*.paa` — то есть структурно это тот же принцип, что в
дизайн-макете (левая навигация + контент справа), просто с иконкой и
подписью в один ряд, а не иконкой над подписью. Поэтому в этой правке
**геометрия и виджеты не перестраивались** — перенесена только палитра.
Полная перестройка вёрстки под точные пропорции макета (уже-панель 76px,
раздельные list+detail панели с точным пикселем макета, скругления,
CSS-подобный grid/шум-текстура) — это отдельная, гораздо более рискованная
задача на 9000+ строк `SM_ClanMenu.c`/255КБ `SM_ClanMenu.layout` без
возможности проверить результат в живом клиенте DayZ; не выполнялась в
этом проходе.

## Что НЕ проверено

- Реальный визуальный результат в клиенте DayZ не проверялся — здесь нет
  игрового клиента. Проверены только: целостность синтаксиса (баланс
  `{}`/`()`, число строк в `.layout` не изменилось), самосогласованность
  палитры.
- `config.bin` — уже собранный (rapified) официальным Addon Builder; он не
  редактировался и не пересобирался, так как правки касались только
  `.layout` и `.c`, которые движок грузит как текст без бинаризации.
  Значит для проверки этого рескина достаточно упаковать PBO без
  Addon Builder (например, `pbo_tool.py pack` из прошлого проекта) —
  бинаризация не требуется, пока не редактируется `config.cpp`.
- Разрешение фактического HUD/меню в игре (масштаб текста, читаемость на
  разных разрешениях) не тестировалось.

## Пошаговый тест (когда будет доступен клиент DayZ)

1. Собрать PBO из `SM_PartyMod/` (prefix `SM_PartyMod`, как в оригинале).
2. Заменить PBO в `@SM_PartyMod/addons` на сервере и у клиента.
3. Зайти в игру, открыть меню клана (`P`) — проверить главное окно, вкладки,
   рынок/аукцион/топы/достижения.
4. Проверить HUD участников клана (нужен клан из ≥2 игроков либо тест
   одним персонажем со включённым `HudEnabled`).
5. Открыть чат клана, проверить цвет плашки канала и текста.
6. Поставить пинг (`T`), проверить цвет пинга на HUD и карте.
7. Проверить статусы «без сознания» (должен остаться красным) и
   «кровотечение» (должен быть янтарным, не зелёным).
